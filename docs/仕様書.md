# Shopping Catch ゲーム仕様書

| 項目 | 内容 |
|---|---|
| タイトル | Shopping Catch（仮） |
| ジャンル | アクション系ミニゲーム |
| 対応端末 | PC、スマートフォン、タブレット |
| 想定プレイ時間 | 1プレイ60秒 |
| 基本操作 | 左右移動のみ |
| 目的 | 制限時間内に商品をできるだけ多くキャッチし、ハイスコアを目指す |
| 対象範囲 | ブラウザで遊べる1人用MVP |
| 最終更新 | 2026年8月17日 |

## 1. コンセプト

画面上部から落ちてくるお菓子や雑貨を、左右に動くカゴでキャッチする短時間アクションゲーム。

操作を左右移動だけに絞り、落下軌道を見極めて追いつく気持ちよさと、得点が即座に変化する分かりやすさを提供する。PCではキーボードまたはゲームエリア内のマウス追従、タッチ端末では画面下部の操作パッドを使い、各端末に適した操作体験を提供する。

## 2. デザイン方針

- キーワード：ポップ、軽快、お買い物、親しみやすい
- 白を基調に、明るい原色とパステルカラーをアクセントに使う。
- UIやキャラクターは丸みのある形状と、弾むようなアニメーションで統一する。
- 操作ボタンは背景とのコントラストを十分に確保する。
- 特定作品のキャラクター、ロゴ、固有の造形・配色は使用しない。既存作品からは「明るさ」「丸み」「軽快さ」のような抽象的特徴のみを参考にする。

## 3. ゲームルール

### 3.1 基本ルール

1. スタート操作後、3秒のカウントダウンを表示する。
2. 商品がゲームエリア上部から順次落下する。
3. プレイヤーはカゴを左右に移動し、商品を受け止める。
4. キャッチすると10点加算し、取り逃すと5点減点する。
5. 60秒経過時に新しい商品の生成を止め、リザルトを表示する。

### 3.2 得点

| イベント | スコア変化 | 表示 |
|---|---:|---|
| 通常商品をキャッチ | 基本10点＋コンボボーナス | カゴ付近に獲得点、スコアを加算色で強調 |
| レア商品をキャッチ | 基本50点＋コンボボーナス | カゴ付近に獲得点、専用エフェクトを表示 |
| 商品を取り逃す | -5点 | 画面下端付近に「-5」、スコアを減算色で強調 |

- 初期スコアは0点とする。
- スコアの下限は0点とし、マイナスにはしない。
- 同一商品に対する得点処理は一度だけ行う。
- ハイスコアは端末内に保存し、次回アクセス時にも表示する。保存できない場合でもゲーム進行は継続する。

### 3.3 コンボ

- 商品を連続でキャッチするたびにコンボ数を1増やす。ゲーム開始時は0コンボとする。
- 商品を取り逃すとコンボは0に戻る。
- 通常商品とレア商品のどちらもコンボ数に含める。
- 1回のキャッチで加算する点数は「商品の基本点＋コンボボーナス」とする。
- コンボボーナスはキャッチ後のコンボ数に応じて以下の通りとする。

| キャッチ後のコンボ数 | コンボボーナス | 通常商品の獲得点 |
|---|---:|---:|
| 1〜4 | 0点 | 10点 |
| 5〜9 | +5点 | 15点 |
| 10〜19 | +10点 | 20点 |
| 20以上 | +20点 | 30点 |

- 5、10、20コンボ到達時は「5 COMBO!」などの節目演出をゲームエリア中央に約0.8秒表示する。
- HUDには2コンボ以上から現在のコンボ数を表示し、リセット時に非表示へ戻す。
- コンボ数に上限は設けない。ボーナスの上限は1商品あたり20点とする。

### 3.4 制限時間

- 初期値：60秒。
- HUDには秒単位で残り時間を表示する。
- 残り10秒から時間表示を警告色にし、1秒ごとに軽く拡大する。
- 残り時間が0になった時点でプレイヤー入力と得点更新を停止する。

### 3.5 難易度進行

以下は調整可能な初期値とする。

| 経過時間 | 生成間隔 | 落下時間の目安 | 同時落下上限 |
|---|---:|---:|---:|
| 0〜19秒 | 1.2秒 | 3.2〜4.0秒 | 3個 |
| 20〜39秒 | 1.0秒 | 2.7〜3.5秒 | 4個 |
| 40〜60秒 | 0.8秒 | 2.2〜3.0秒 | 5個 |

- 商品の水平位置、種類、落下速度には範囲内でランダム性を持たせる。
- 商品同士が極端に重ならないよう、生成位置に最小間隔を設ける。
- 初見で回避不能な急加速や途中での不規則な軌道変更は行わない。

## 4. ゲームオブジェクト

### 4.1 プレイヤー（カゴ）

- ゲームエリア下部に配置し、水平方向にのみ移動する。
- ゲームエリア外へ出ないよう位置を制限する。
- 初期位置は中央とする。
- 移動は押下中に継続し、左右同時入力時は移動を停止する。
- 推奨移動速度はゲームエリア幅の約0.8倍/秒とし、端末サイズに比例させる。
- 表示幅はゲームエリア幅の約19%を基準とし、72〜160pxの範囲に制限する。
- 当たり判定はカゴ全体ではなく、商品を受け止める上部の口付近に設定する。
- カゴの口は表示幅の88%、表示高の30%を判定範囲とし、見た目との一致と操作しやすさを両立する。

### 4.2 落下商品

- 通常商品はお菓子3種、雑貨3種の計6種以上を用意し、基本点を10点とする。
- 通常商品は種類による得点差を設けない。
- 表示サイズはゲームエリア幅の約9.5%を基準とし、36〜72pxの範囲に制限する。
- 当たり判定は絵文字の透明余白と形状を考慮し、ドーナツ、キャンディ、クッキー、ぬいぐるみ、帽子、ボトルごとに矩形の縦横比を設定する。
- 商品は画面上端の内側に収まる位置から生成し、一定速度で真下へ落下する。
- カゴと接触したらキャッチ、ゲームエリア下端を完全に越えたらミスと判定して消去する。
- 1フレーム前から現在位置までの落下経路を含めて交差判定し、高速落下時の判定抜けを防止する。

### 4.3 レア商品

- レア商品は通常商品と明確に区別できる「ゴールド商品」1種以上を用意し、基本点を50点とする。
- 各商品生成時に5%の確率で通常商品の代わりに出現する。
- 1プレイにつき最低1個は出現する。50秒経過時点で一度も生成されていない場合、次の商品をレア商品にする。
- 同時に存在できるレア商品は1個までとする。
- 落下速度は通常商品と同一にし、当たり判定はプレゼント画像の形状に合わせて設定する。
- 光沢、星形の粒子、輪郭などを用い、色だけに頼らずレア商品であることを表現する。
- レア商品を取り逃した場合も通常商品と同じく5点減点し、コンボをリセットする。

## 5. 画面と状態

### 5.1 画面状態

| 状態 | 主な表示 | 利用可能な操作 |
|---|---|---|
| タイトル | タイトル、遊び方、スタート、ハイスコア | スタート |
| カウントダウン | ゲーム画面、3・2・1 | 操作不可 |
| プレイ中 | HUD、ゲームエリア、端末別操作案内 | 左右移動 |
| 一時停止 | 停止表示、再開、タイトルへ | 再開、終了 |
| リザルト | 今回のスコア、ハイスコア、もう一度、タイトルへ | 再プレイ、終了 |

- ブラウザタブが非表示になった場合は自動的に一時停止する。
- リザルトから「もう一度」を選ぶとスコア、時間、商品、カゴ位置を初期化して再開する。

### 5.2 プレイ画面の構成

```text
┌──────────────────────────┐
│ SCORE 120       TIME 42  │  HUD
├──────────────────────────┤
│       商品     商品      │
│                          │
│             商品         │  ゲームエリア
│          ［カゴ］        │
├──────────────────────────┤
│ PC: マウス / ← → / A D │  PC用案内
│ または                   │
│      ［←］    ［→］      │  タッチ用固定パッド
└──────────────────────────┘
```

- HUD、ゲームエリア、操作UIは視覚的かつ構造的に分離する。
- 操作UIがゲームエリアに重ならないようにし、指で商品やカゴを隠さない。
- HUDはゲーム中、常に視認できる位置に固定する。

## 6. 入力仕様

### 6.1 PC

| 動作 | 操作 |
|---|---|
| マウス移動 | ゲームエリア内でカゴをポインターの水平位置へ追従 |
| 左移動 | `ArrowLeft` または `A` |
| 右移動 | `ArrowRight` または `D` |
| 一時停止／再開 | `Escape` または `P` |
| スタート／再プレイ | `Enter` または `Space` |

- `keydown` で移動開始、`keyup` で停止する。
- マウス操作はクリックを必要とせず、プレイ中の `pointermove` でカゴを移動する。
- マウス座標をゲームエリア内の座標へ変換し、カゴが左右端から外へ出ないよう補正する。
- 対象キー入力時のブラウザ既定スクロールを抑止する。
- キーボード利用時はキー案内を表示し、タッチ操作パッドは原則非表示にする。

### 6.2 スマートフォン／タブレット

- 画面下部に左右ボタンを固定表示する。
- `pointerdown` で移動開始し、`pointerup`、`pointercancel`、領域外への移動で停止する。
- 長押し中は連続移動できる。
- マルチタッチによる左右同時押下時は移動を停止する。
- タッチ操作中のスクロール、選択、ダブルタップ拡大による誤操作を操作領域内で抑止する。
- 押下中は色、縮小、影の変化などでアクティブ状態を即時表示する。
- ボタンの視認領域・タップ領域は各辺44px以上、推奨56px以上とする。
- 端末のセーフエリアを考慮し、下端余白に `env(safe-area-inset-bottom)` を加える。

### 6.3 入力方式の表示判定

- 画面幅768px以下では下部操作パッドを表示する。
- 加えて `pointer: coarse` の端末では、画面幅にかかわらず操作パッドを利用可能にする。
- PC向けの細かいポインターではキー案内を表示し、粗いポインターでは操作パッドを表示する。
- レイアウト切替後も進行中ゲームのスコアと残り時間を維持する。

## 7. レスポンシブレイアウト

### 7.1 PC（769px以上）

- ゲーム全体を画面中央に配置する。
- ゲームエリアの最大幅は930px、縦横比は9:8とし、画面の高さにも収まるよう幅を制限する。
- キー案内をゲームエリア下に表示し、画面下端で見切れないよう上寄りに配置する。
- 操作パッドは、タッチ主体端末でない限り非表示とする。

### 7.2 モバイル縦向き（768px以下）

- 上からHUD、ゲームエリア、固定操作パッドの順に配置する。
- 操作パッド分の高さを本文側にも確保し、ゲームエリアと重ならないようにする。
- 左右ボタンは親指で届きやすい下部左右へ配置する。
- ボタン間には誤タップを防ぐ十分な間隔を設ける。
- タイトル画面ではPC専用の「Enter / Space」案内を非表示にする。
- 一時停止・リザルトの主要ボタンはダイアログ内幅以下に制限し、中央に配置する。
- リザルトは買い物袋画像を非表示にして余白と文字サイズを圧縮し、すべての操作を画面内に表示する。

### 7.3 モバイル横向き

- 高さが不足する場合はHUDをコンパクト化し、操作パッドを左右端の下寄りへ配置する。
- ゲームエリアの高さを優先し、操作ボタンを画面左右端へ配置する。ボタン以外の操作パッド領域は入力を遮らない。
- `orientation: landscape` および高さ条件を組み合わせたメディアクエリで切り替える。

### 7.4 タブレット

- 幅769px以上の粗いポインター端末でもタッチ操作パッドを表示する。
- 上部タイトルとゲーム画面をひとまとまりとして縦中央に配置し、間に過剰な空白を設けない。

## 8. 演出・フィードバック

### 8.1 キャッチ

- 商品を短く拡大・縮小させて消す。
- カゴを軽く弾ませる。
- 実際の獲得点を約0.6秒表示し、上方向へ移動しながらフェードアウトさせる。
- 短く明るい効果音を再生する。
- レア商品では金色の粒子と専用効果音を追加する。

### 8.2 ミス

- 「-5」を落下地点付近に約0.6秒表示する。
- HUDのスコアを一瞬だけ揺らす、または減算色に変える。
- キャッチ音と区別できる短い効果音を再生する。

### 8.3 アクセシビリティへの配慮

- 色だけに依存せず、「+10」「-5」の文字と動きでも結果を伝える。
- `prefers-reduced-motion: reduce` では揺れや拡大を抑え、フェード中心にする。
- 効果音のオン／オフボタンを設け、設定を端末内に保存する。
- フォーカス位置を明確にし、タイトルからリザルトまでキーボードだけで操作可能にする。
- テキストと背景は原則WCAG AA相当のコントラストを確保する。

### 8.4 ハイスコア更新演出

- プレイ開始時点の保存済みハイスコアを、そのプレイで更新判定する基準値として保持する。
- プレイ中に初めて基準値を上回った瞬間、HUD付近に「NEW HIGH SCORE!」を約1.2秒表示し、スコアを発光させる。
- 基準値が0点の場合も、初めて0点を上回った時点で更新演出を行う。
- 1プレイ中の「NEW HIGH SCORE!」演出は一度だけとし、その後もスコア自体は通常どおり更新する。
- ハイスコアを更新してゲームを終了した場合、リザルトで王冠または星の紙吹雪と「ハイスコア更新！」を表示し、専用ジングルを再生する。
- 未更新時は今回のスコアと従来のハイスコアを通常表示する。
- `prefers-reduced-motion: reduce` では紙吹雪を使用せず、静的な王冠と文字の強調へ置き換える。

## 9. サウンド

- BGM：軽快で短時間プレイに適したループ曲。
- 効果音：スタート、キャッチ、ミス、残り10秒、終了、ボタン押下。
- 初回のユーザー操作後にのみ音声再生を開始する。
- ミュート時はBGMと効果音を停止する。

## 10. 技術仕様

- 描画更新は `requestAnimationFrame` を使用し、移動量は経過時間に基づいて計算する。
- ゲームロジックと描画を分離し、端末のフレームレート差で速度が変化しないようにする。
- 背景遷移後の大きな経過時間は無視し、自動一時停止から復帰させる。
- 当たり判定はカゴ上部と商品の形状別矩形の交差を基本とする。
- 落下商品は前フレームから現在位置までを覆う矩形で判定し、フレーム間のすり抜けを防止する。
- 画面リサイズ時は座標を新しいゲームエリア寸法へ正規化し、場外に出ないよう補正する。
- ハイスコア、音声設定は `localStorage` に保存する。
- 外部通信を必須とせず、初回ロード完了後は通信障害がゲーム進行に影響しない構成とする。

### 10.1 調整可能パラメータ

以下はコード内に散在させず、一か所にまとめて管理する。

- 制限時間
- キャッチ点、ミス減点、スコア下限
- コンボの段階、ボーナス、節目演出
- プレイヤー移動速度
- 商品の種類、表示サイズ、落下速度
- レア商品の基本点、出現確率、最低出現保証
- 商品生成間隔、同時落下上限、生成位置の最小間隔
- 当たり判定の補正値
- 各演出の時間、音量

## 11. 非機能要件

- 最新のChrome、Edge、Safari、Firefox各安定版を対象とする。
- iOS SafariおよびAndroid Chromeの縦向き・横向きで操作できること。
- 通常プレイ時は目標60fps、最低30fpsを維持すること。
- 主要ゲーム素材のロード完了後にスタート可能とし、ロード中であることを表示する。
- 画像には代替テキスト相当の意味を持つ名称を付け、UIボタンにはアクセシブルネームを設定する。

## 12. 受け入れ基準

1. スタート後に3秒カウントダウンを経て、商品が上から落下する。
2. PCで矢印キーとA/Dキーの両方を使ってカゴを左右移動できる。
3. PCでゲームエリア内のマウス位置へカゴが追従し、左右端から外へ出ない。
4. 幅768px以下、または粗いポインターの端末で下部固定パッドを操作できる。
5. 操作ボタンのタップ領域が44×44px以上あり、押下中の視覚フィードバックがある。
6. 操作UIが主要な落下物を隠さず、操作を妨げない。
7. キャッチ1回につき「商品の基本点＋コンボボーナス」が一度だけ加算され、ミス1回につき5点が一度だけ減算される。
8. 商品の形状に応じた判定がカゴの口と交差した場合にキャッチされ、高速落下時にも判定が抜けない。
9. 連続キャッチでコンボ数と規定のボーナスが加算され、ミスするとコンボが0へ戻る。
10. レア商品が1プレイに最低1個出現し、キャッチ時に基本50点と専用演出が適用される。
11. スコアは0未満にならず、変化が即座にHUDへ反映される。
12. 60秒でゲームが終了し、終了後に入力や得点が反映されない。
13. リザルトに今回のスコアとハイスコアが表示され、再プレイできる。
14. スマホの一時停止・リザルト画面ですべてのテキストとボタンが見切れず、主要ボタンが中央に表示される。
15. 保存済みハイスコアを初めて上回った時と、更新したリザルトで専用演出が一度ずつ表示される。
16. 画面回転・リサイズ後も、カゴと商品がゲームエリア外へ不正に配置されない。
17. タブが非表示になるとゲームが一時停止し、復帰時に時間や商品が飛ばない。
18. PC、モバイル縦向き、モバイル横向き、タブレットで操作案内とレイアウトが適切に切り替わる。

## 13. MVP対象外

- オンラインランキング、ログイン、クラウド保存
- 複数ステージ、ストーリーモード
- アイテムごとの特殊効果、パワーアップ
- 課金、広告、SNS共有
- 対戦・協力プレイ

これらは基本プレイループの評価後に追加検討する。
